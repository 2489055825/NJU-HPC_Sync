## 技术依据

rsync 的受保护参数通道绕过远端 shell，但远端 rsync 会展开源和目标路径通配符；没有匹配时直接使用编码后的原始参数。如果字面源 `data[1]` 不存在，而额外反斜杠名称 `data\[1]` 存在，仅转义仍会选错源。因此下载使用 `--rsync-path='CDPATH= cd -P <完整引用的源目录> && exec rsync'`，将真实路径只交给 shell 的字面值目录操作；协议源固定为 `./`，不产生可变 glob 或回退路径，并保留 rsync 的 sender 检查。相对路径前置 `./`，防止 CDPATH 搜索和 cd 选项解释。cd 失败时不会启动远端 rsync；不先检查再重新解析原路径。使用 `--protect-args`；不支持该通道的远端报错，不退回可能选错目录的模式。

真实传输测试发现，上传即使使用受保护通道，原样 `data[1]` 目标仍可选中 `data1`；转义目标在目录不存在时会回退为带额外反斜杠的名称。因此上传改为 `--old-args` 加 `shlex.quote` 完整路径，让远端 shell 产生一个字面值 argv，远端 rsync 不进入受保护参数的 glob 展开。该选项需本地 rsync >=3.2.4；远端按 rsync >=3.1 支持，目前实机验证为3.2.7。安装依赖和教程同步更新。

两方向的相对目录均先加 `./`，也避免上传 `:data` 被拼接成 `host::data`、误切换到 rsync daemon 模块语法。真实传输测试通过显式 SSH 替身运行 rsync，阻止意外进入 daemon 网络连接。

依据：[rsync 参数文档](https://www.samba.org/ftp/rsync/rsync.1.html)、[3.2.7 read_args](https://github.com/RsyncProject/rsync/blob/v3.2.7/io.c#L1232-L1244)、[glob_match/glob_expand](https://github.com/RsyncProject/rsync/blob/v3.2.7/util1.c#L600-L736)。

启动状态采用只读内核锁探测作兜底：锁仍属于同一任务时，初始客户端退出不能证明任务结束。worker 是任务状态的持续写入者，取消请求独立保存；不在提交父进程中并发覆盖 worker 的任务记录。

恢复取消已知进程后也重新核对同任务内核锁；如果仍有未知持有者，不把停止一个已登记会话当作全部停止，保留 `interrupted, terminal=false, RECOVERY_REQUIRED`。
