# CLI Implementation Plan

> **For agentic workers:** Use executing-plans to implement inline, task by task; request one independent review of the final changes. Steps use checkbox syntax for tracking.

**Goal:** Provide a headless CLI whose independently owned rsync tasks survive a closed caller terminal and expose reliable results, cancellation and busy responses.

**Architecture:** Dispatch CLI commands before importing Qt. A private task store and inherited Linux flock coordinate a detached per-task worker, while ordinary CLI clients wait/read/cancel through durable records. Reuse existing rsync, credentials and TOTP code; share a process lock and persistent TOTP window guard with the GUI.

**Tech Stack:** Python 3.11, argparse, subprocess, fcntl, SQLite, existing pexpect/PySide6/pyotp, pytest, PyInstaller.

**Spec:** `docs/superpowers/specs/2026-11-12-cli-design.md` (user approved).

## Global Constraints

- CLI tasks never create QApplication or request interactive authentication.
- No credentials in argv, environment, state, logs or results; use existing credential names only.
- Default normal sync; mirror requires explicit `--mirror`, regardless of the Profile default.
- One transfer per system user including updated GUI; do not queue jobs.
- Closing or interrupting a waiting client does not cancel its worker; cancellation is explicit.
- No real HPC connection or user configuration changes during verification.
- No installation, release publication or shared-branch push is included.
- Work in the managed `codex/cli` worktree. User already authorized implementation; proceed continuously without another plan approval.

## Review Focus

- Worker death while rsync/SSH still lives must never authorize a second transfer or signal unrelated reused PIDs.
- A waiting client lost during startup cannot leave an accepted task without an executor or unlock the worker's lease.
- JSON errors and partial results must distinguish submission, transfer, cancellation and history-write outcomes.
- Repeated CLI/GUI authentication cannot reuse the same TOTP time window or spill partial credential echoes.
- A missing/corrupt readonly database must not be initialized or silently repaired by query commands.

## Task 1: Private runtime records, lease and persistent TOTP

**Files:** Create `app/runtime.py`, `tests/test_runtime.py`; modify `app/totp.py`.

**Interfaces:** `TaskStore(root: Path | None)` provides create/read/update/list/resolve task records and cancellation requests. `TransferLease.acquire(owner: dict)` returns a closeable held flock or raises `BusyError`; `TransferLease.adopt(fd)` takes ownership after exec. Runtime helpers write private JSON atomically and verify Linux process start identity. `PersistentTotpReplayGuard(path: Path | None).claim(config, counter)` implements the existing guard protocol under a file lock.

## Final verification and delivery

- All six tasks completed in the managed `codex/cli` worktree; changes remain available for review without integration into main, installation or publication.
- The original 146 cases remain passing. Final full suite with strict warnings and the frozen executable enabled: **204 passed in 34.64s**, no skips. Command: `NJU_HPC_SYNC_TEST_EXECUTABLE=<absolute-built-executable> QT_QPA_PLATFORM=offscreen conda run -n hpc-sync pytest -q -W error`.
- `compileall`, shell script syntax and `git diff --check` pass.
- A PyInstaller build was validated after the existing build script's C++ runtime copy step. Frozen CLI re-executes its worker, detaches, waits, cancels and survives the caller PTY closing. No installed package was changed.
- Real rsync client/server processes ran over a local SSH stand-in, with no network connection: dry-run preserves the target, explicit mirror deletes the surplus file, upload/download transfer actual contents, and Chinese/space-containing paths work.
- Independent review found four Important issues: relative path snapshots, cancellation after PTY leader exit, equivalent Base32 encodings and structurally corrupt task records. Each was reproduced in failing regression tests and repaired. The aggregate preview count gap was treated as part of the promised interface and repaired before truncation. No review findings were left deferred.
- Cancellation uses verified session membership and pidfds. This Conda Python omits its optional pidfd wrappers, so the implementation uses the verified Linux x86_64 syscall equivalents when needed; unsupported safe signaling remains an explicit recovery condition rather than falling back to unchecked PID signals.
- Live HPC authentication and native desktop window-manager behavior were not exercised. Tests use synthetic credentials and local transfers; there is no agent-specific message integration or background queue.
