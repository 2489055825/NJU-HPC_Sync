# SSH Host 管理设计

## 目标

在“管理”菜单增加“Host 管理”，让用户直接查看和编辑用户 SSH 主配置文件 `~/.ssh/config`。应用继续从主文件及其 `Include` 文件读取 Host；本功能只允许写入主文件，不修改 Include 子文件。

## 方案

采用带保存能力的原始文本编辑对话框，保留用户现有的排版、注释和 OpenSSH 指令。结构化表单无法完整覆盖 OpenSSH 配置，外部编辑器又无法提供保存确认和 Host 列表刷新，因此不采用这两种方案。

## 行为

- 菜单路径为“管理 → Host 管理”。打开时读取 `Path.home() / ".ssh" / "config"`；文件不存在时显示空编辑器，并提示保存会创建文件。
- 对话框显示文件路径、可编辑多行文本、重新加载、保存和取消/关闭按钮。打开后文件发生外部变化时，重新加载前提示用户，避免覆盖外部修改。
- 保存前检查文本可被安全地写入；至少检查 UTF-8 编码和基本配置行格式，允许 OpenSSH 的未知指令和 Include。解析失败时不写文件，并显示行号和原因。
- 写入前创建同目录备份 `config.bak`，使用同目录临时文件写入并 `os.replace` 原子替换；继承或恢复原文件权限，主配置文件默认为 `0600`，SSH 目录不存在时创建为 `0700`。
- 写入失败保留原文件并显示错误。保存成功后重新读取 Host，下拉列表立即刷新；当前 Profile 的 Host 若不再存在，沿用现有缺失 Host 提示和阻止执行逻辑。
- 备份同样通过临时文件原子替换，不跟随既有备份的符号链接；主配置若为符号链接则拒绝覆盖，保留链接和目标。文件读取和快照来自同一份字节，保存操作在替换前再次检查外部修改。
- 不显示、不记录凭据或私钥内容；编辑器只处理 SSH 配置文本。保存前确认提示包含文件路径和备份路径。

## 非目标

- 不编辑 `Include` 引用的子文件。
- 不执行 `Match exec`、`ProxyCommand` 或其他配置命令，不建立 SSH 连接来验证配置。
- 不将配置内容写入 SQLite、日志、截图或 Release 产物。

## 验收

- 测试覆盖新建文件、保留现有权限、备份、原子保存、保存失败回滚、外部修改检测、非法 UTF-8/格式提示、取消不写入和菜单打开入口。
- 运行完整 pytest、compileall，并用临时 HOME 的 Qt 界面检查对话框布局和保存后 Host 下拉刷新。
