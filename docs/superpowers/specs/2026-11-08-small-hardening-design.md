# 小幅加固与回归测试设计

## 意图

在保持现有同步、认证、镜像确认和 UI 生命周期行为不变的前提下，处理本地写入失败时的用户反馈，并为当前没有覆盖的错误路径补充回归测试。

## 目标

- 凭据保存或删除遇到 `OSError` 时显示可理解的错误，保留磁盘上的旧凭据和当前编辑状态。
- 日志导出遇到 `OSError` 时显示错误，不让异常直接离开 Qt 槽函数。
- 为凭据失败回滚、日志导出失败、Profile 操作、preflight 缺少依赖、rsync 退出码和认证边界补充测试。
- 继续使用临时目录和合成数据，不接触真实凭据或 HPC 主机。

## 非目标

- 不改变 rsync argv、路径规范化、TOTP 生成、主机指纹确认、镜像预览绑定或任务取消流程。
- 不在没有真实集群提示样本的情况下扩大 SSH prompt 匹配规则。
- 不重新设计数据库架构或安装新的运行时依赖。

## 方案

1. **只补测试**：风险最低，但本地写入失败仍缺少明确的产品反馈。
2. **小幅加固并补测试（选定）**：只处理凭据和日志导出的 `OSError`，其余问题通过测试记录边界。改动小、行为可预测，适合当前版本。
3. **扩大认证协议兼容性**：修改 SSH prompt 匹配或强制英文环境；需要真实 HPC 的提示文本，暂不采用。

## 实现

### 凭据对话框

在保存和删除前构造候选凭据映射。只有 `CredentialStore.save()` 成功后，才更新对话框内存状态、编辑名称、列表和 `credentials_changed` 信号。捕获 `OSError`、`RuntimeError` 和已有的校验错误，使用现有警告对话框显示失败原因。

### 日志导出

在 `MainWindow._save_log()` 中捕获 `OSError`，显示写入失败提示；成功路径保持现状。

### 测试

- 使用 monkeypatch 模拟凭据保存失败，验证原文件和对话框内存状态不被破坏。
- 模拟日志文件写入失败，验证出现警告且窗口仍可继续使用。
- 补充 Profile 新建/编辑/删除边界、缺少 `rsync`/`ssh` 的 preflight、`friendly_exit_message` 和手工认证取消/空密码测试。
- 保持现有完整测试、编译检查和 offscreen 启动检查作为验收条件。

## 验收标准

- 新增测试在修改前能复现目标失败路径，修改后通过。
- 原有 121 个测试全部通过。
- `python -m compileall -q app main.py` 通过。
- `git diff --check` 通过。
- 不产生真实凭据、远程连接或非临时用户数据。
